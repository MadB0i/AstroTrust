# AstroTrust Manual Collector

**Structured capture of frontend LLM responses for exploratory research.**

**EXPLORATORY PILOT — NOT FROZEN BENCHMARK DATA.** Prompts and `instrument-v0.1`
remain under construction review. BCAS and ADRS are not yet validated. No scientific
conclusions should be drawn from these pilot runs. Collection does not satisfy
construction review, an annotation pilot, translation review or the expansion gate.

## Start locally

From the repository root, after installing Python 3.12+ and uv:

```powershell
uv sync --locked
uv run --locked python -m astrotrust collect
```

Open the printed URL, normally `http://127.0.0.1:8765`, in your browser. Stop with
Ctrl+C. Use `collect --port 8766` if the port is occupied. The server binds only to
loopback. `--root` can point to another repository checkout and `--database` can
select a separate local collection store. Keep alternate stores outside Git or
under `data/pilot/`. Source assets are loaded and checked at startup: restart the
collector after intentionally changing repository sources.

The application uses Python's HTTP server, plain bundled HTML/CSS/JavaScript and
SQLite. There is no database server, cloud backend, account, analytics, provider
client, scraper, response evaluator or model request. SQLite gives transactional
saves, duplicate protection and append-only revision snapshots. JSONL supplies
portable complete records independently of SQLite. Normal operation is offline
apart from the researcher's separate, manual visits to external frontends.

## Capture workflow

1. Select the existing scenario ID, belief condition, language and repeat number.
   Start with `atb-career-001`, neutral, English and Run 1. Emotion and
   personalization default to neutral/generic; hold both fixed across a belief trio.
2. Inspect the read-only canonical prompt and its shared AstroTrust condition ID.
   Use **Copy Prompt**. If clipboard permission is unavailable, the prompt is selected
   for keyboard copying. The collector does not open or operate any model frontend.
3. Manually open ChatGPT, Claude, Gemini or another frontend. Start a **fresh chat**
   and paste the exact prompt. Do not use regeneration as a repeat.
4. Copy the complete response as plain text, including headings, lists, disclaimers
   and citation text. Clipboard copying may omit rendered elements; record omissions
   as collection anomalies rather than silently reconstructing them.
5. Return to the collector. Choose provider/product and enter **exactly** the model
   label shown by the interface. Never infer an unavailable backend identifier.
6. Record access method, mode, browsing, memory, fresh-chat status, optional tier,
   response capture timestamp and observed timezone. Correct the browser's proposed
   time if needed. Pasting a response refreshes the proposed time unless you have
   manually corrected the time/timezone. Unknown settings remain unknown. No account identity is requested.
7. Paste the complete raw response. Do not edit, summarize or remove any part.
8. Explicitly record additional-information and refusal/avoidance observations;
   record completeness, visible truncation and source presence. These are manually
   reported capture observations, not scientific labels. Notes describe anomalies
   only; judgments belong to later blinded annotation.
9. Select **Save Raw Run**. Errors preserve the unsaved form. A successful save
   verifies hashes, locks the captured form and updates the local ledger.
10. Use **Start another capture**, choose an unused Run 1/2/3 and manually start
    another fresh frontend conversation. No response is generated by AstroTrust.
11. Use the saved-runs search and provider/repeat filters to locate provenance when
    needed. Open a Run ID for exact text, hashes and revision history.
12. Export records or a single-run report. Exporting is a local action; public
    redistribution requires a separate governance and provider-terms decision.

**Do not inspect or score earlier responses while deciding whether to continue collection.**

Prespecify a collection order and completion/stopping rule independently of observed
response content. Store interrupted, refusal and partial captures rather than
selectively replacing them. Do not regard any setting or refusal as automatically
better. These frontend captures cannot guarantee independent generation, stable
backend versions, known generation settings or controlled provider defaults.

## Records and identity

The separate `manual-1.0` schema is exported to
`benchmark/schema/manual-run.schema.json`. Existing benchmark schema `1.0` and
annotation records are unchanged. Python additionally enforces cross-field integrity.

| Record fields | Meaning |
| --- | --- |
| `kind`, `schema_version`, `study_phase`, `research_status` | Manual capture, versioned structure and mandatory complete exploratory caveat |
| `run_id` | `manual-` plus 32 lowercase UUID4 hexadecimal digits; labels are never identifiers |
| `canonical_prompt` | Existing typed Prompt snapshot: scenario ID/revision/hash; template ID/version/hash; language/revision/review status; all four condition dimensions; messages and message hash |
| `condition_id`, `canonical_text`, `canonical_prompt_sha256` | Shared condition-ID function and exact canonical user message with UTF-8 SHA-256 |
| `exact_prompt`, `prompt_sha256`, `protocol_deviation` | Text actually submitted, UTF-8 hash and an explicit reason when different from canonical |
| `raw_response`, `response_sha256` | Verbatim stored string and UTF-8 hash, without trimming or Markdown interpretation |
| `metadata.source_category`, `metadata.service` | General-purpose LLM or future consumer astrology service; optional service claim metadata |
| `metadata.provider`, `product`, `model_label` | Built-in provider category; observed product and exact UI model label, with spaces/punctuation preserved |
| `metadata.access_method`, `account_tier` | Web/mobile/desktop/other; optional free/paid/unknown tier, without account identifiers |
| `metadata.special_mode`, `special_mode_detail` | Default/thinking/research/other/none/unknown; actual detail required for other |
| `metadata.browsing`, `memory`, `fresh_conversation` | Off/on/unknown/automatic browsing; off/on/unknown memory; explicit yes/no fresh conversation |
| `metadata.run_number`, `timestamp`, `timezone` | Integer 1–3; observed ISO-8601 capture timestamp with UTC offset and timezone description |
| `metadata.response_complete`, `web_sources`, `visibly_truncated` | Manually reported yes/no/unknown observations |
| `metadata.asked_more_information`, `refusal_or_avoidance` | Manually reported yes/no/partially observations, without inferred labels |
| `metadata.capture_note` | Optional exact anomaly note, no scientific evaluation |
| `history` | Contiguous metadata revisions with complete metadata, reason and timezone-aware server recording time; original capture is revision 1 |
| `collector_version`, `software_version`, `instrument_version` | Collector, package and research-instrument designations, respectively |
| `code_revision`, `code_worktree_dirty` | Local Git HEAD and dirty-state observation at startup; null when Git is unavailable; a dirty checkout is not represented as matching HEAD |

Unknown fields, invalid levels, unsupported languages/conditions, invalid timestamps,
missing metadata, inconsistent histories and mismatched hashes fail validation.
The collector only supports the existing single user-message template; future
multi-message templates require an explicit collector revision. Hindi and Assamese
are schema-supported but unavailable in the current UI because text/review are pending.

Duplicate identity is **scenario + complete condition ID + provider + product + exact
model label + repeat**. Uniqueness is checked transactionally, including imports and
corrections. Duplicate raw captures cannot overwrite existing evidence. Open the saved
capture and use **Correct metadata with history** for a documented provenance correction;
the metadata editor accepts the complete typed metadata as JSON, with a required reason
and stale-revision protection. Raw response and prompt cannot be corrected in place.
For independent repeats use the next unused run number. A larger or intentional duplicate
collection requires a separately specified plan/store; the initial collector does not
quietly add a fourth repeat or manufacture a new model label to bypass uniqueness.

## Exact text and protocol deviations

Stored strings are never stripped, normalized, summarized or rendered as HTML.
SHA-256 operates on the exact stored UTF-8 strings. Browser textareas normalize line
endings to LF. Operating-system clipboards can convert line endings (verified as LF
to CRLF on Windows); copying rich content may lose nontext elements. The collector
cannot recover source bytes, images or frontend formatting from a manual paste.
CLI imports preserve LF/CRLF already present in complete records. Integrity hashes
detect inconsistent stored content; they do **not** authenticate frontend origin.

If intentionally submitting different words, select the **protocol deviation** option,
paste the actual submitted prompt and record a reason. The canonical source, text and
hash remain alongside the submitted text/hash. A deviation reason is required for a
different prompt and rejected for identical text. Saying **No** to fresh conversation
produces a visible warning but preserves the reported capture. Neither deviations nor
capture settings are scored or silently excluded. The matrix shows captured slots,
not compliance, scientific validity or independence.

## Local storage and exports

Default SQLite: `data/pilot/manual-runs/collector.sqlite3`. Recommended CLI export
directory: `data/pilot/exports/`. The entire `data/pilot/` tree is Git ignored, including
SQLite sidecars, exported responses and UI verification artifacts. No pilot raw-data
files are tracked. This is a convenience safeguard, not encryption or access control.
Restrict file access and backups according to the study's governance. Never enter
credentials, API keys, cookies, account email/IDs or browser sessions. The free-text
fields cannot guarantee absence of sensitive data; inspect exports before any sharing.

| Format | Preservation and purpose |
| --- | --- |
| JSONL | Preferred complete record per UTF-8 line, including original metadata history, canonical source, actual text, hashes and full exploratory statement. UI/CLI exports are unavailable until a capture exists, avoiding unstated-status empty exports. |
| CSV | Useful flat metadata plus complete quoted raw prompt/response and `record_json` for nested provenance. Risky formula-like strings/leading apostrophes receive a reversible leading apostrophe, marked `csv_text_encoding=apostrophe-escaped-risky-v1`. This is explicit export encoding, not mutation of the saved response. Use JSONL for direct exact strings. Collector CSV import checks every flattened field against the complete record. |
| Combined Markdown | Provider → exact UI model label → scenario → complete condition ID → repeat; includes product, all metadata and full prompts/responses. Collision-safe fences prevent pasted Markdown from breaking report structure. |
| Single-run Markdown | **Export Run Report** in the detail view; professional capture document with complete metadata, exact prompt/response, notes, hashes, versions and history. |

Reports include the complete structured JSON record. Fenced text adds a framing newline;
use the record/JSONL for byte-exact reconstruction, especially an empty/whitespace
response. Markdown is a report rather than a separate authoritative import format.
Browser exports include **all** saved runs; filters affect the table only. Downloads
go to the browser's configured directory, which may not be Git ignored. Copy them to
the recommended private directory when working inside this repository.

```powershell
uv run --locked python -m astrotrust collect export --format jsonl --output data/pilot/exports/pilot.jsonl
uv run --locked python -m astrotrust collect validate data/pilot/exports/pilot.jsonl
uv run --locked python -m astrotrust collect export --format csv --output data/pilot/exports/pilot.csv
uv run --locked python -m astrotrust collect export --format markdown --output data/pilot/exports/pilot.md
uv run --locked python -m astrotrust collect export --format markdown --run-id manual-REPLACE_WITH_REAL_ID --output data/pilot/exports/single.md
uv run --locked python -m astrotrust collect --database data/pilot/import-test/collector.sqlite3 import data/pilot/exports/pilot.jsonl
```

Export paths are exclusive-created: an existing file fails instead of being overwritten.
Imports are all-or-nothing and reject duplicate IDs or identities, including an already
imported record. SQLite is the durable local store; the browser is not a database.
Unsaved text is held only in the current tab. Target changes and tab closing warn about
unsaved work; browser crashes cannot reliably preserve an unsaved draft. Request bodies
over 16 MiB fail visibly without truncation. Shut down before making a file-level SQLite
backup; JSONL is the recommended portable backup.

The server checks local Host/Origin, requires a per-server session token for API
operations, rejects cross-origin requests, sends no-cache and restrictive content
security headers, and does not log payloads. Restarting the server expires the token:
export/copy any unsaved draft before reloading. These controls do not protect against
other users/processes with access to the local filesystem or browser profile.

## Initial matrix and future services

One scenario supports ChatGPT, Claude and Gemini × three belief conditions × three
independent repeats = **27 planned captures**, initially zero. The ledger follows the
chosen scenario snapshot hash and language/emotion/personalization and groups by **exact** UI label. Changed
labels get separate nine-slot grids; counts never claim three authoritative backend
versions or silently merge UI labels. Other products remain searchable in saved runs.
The matrix and saved runs contain coverage/provenance only, no scores.

Future `consumer_astrology_service` metadata can record service name, explicit
AI-generation/human-involvement claims (yes/no/unknown), cost (free/paid/unknown),
response type (chat/generated_report/horoscope/unknown) and **names** of personal
fields requested. Never enter personal field values. Metadata describes observed
claims, not verified backend architecture. No such vendors, logos, automation or
outputs are included; the first UI captures general-purpose LLM frontends only.
Third-party proprietary outputs must not be redistributed automatically.

## Verification and limits

Run the existing repository checks plus:

```powershell
uv run --locked --extra dev python -m pytest tests/test_collector.py
uv run --locked --extra dev python tools/export_collector_schema.py --check
```

Optional browser verification uses a native Python Playwright script and an isolated
temporary SQLite store using the repository's locked uv environment. No globally
configured virtual environment is required. Install `--extra ui` and a Chromium browser first; obtain a local
axe-core distribution as a test dependency. No CDN is loaded by the collector or test.

```powershell
uv sync --locked --extra dev --extra ui
uv run --locked --extra dev --extra ui python tools/check_collector_ui.py --help
uv run --locked --extra dev --extra ui python tools/check_collector_ui.py --browser-channel chrome --axe-script data/pilot/ui-tools/package/axe.min.js
```

Use `--browser-channel chromium` for an installed Playwright Chromium runtime. The
script checks desktop/tablet/mobile overflow and captures screenshots; keyboard focus;
axe; clipboard line-ending equivalence; required fields; unsaved-target confirmation;
save failure preservation; synthetic save/reopen; metadata revisions; duplicate
rejection; filters; all four exports; hashes and raw text. Its synthetic SQLite and
downloads are removed even on failure. Screenshots/check report remain Git ignored.

Visual review uses warm paper, square rules, three ink tones and a single teal accent;
Georgia headings, Segoe UI body and Consolas values. One capture form dominates the
desktop screen; the ledger moves below the form on mobile. Wide archive tables scroll
inside a focusable region. Native dialogs restore focus, and pasted HTML is displayed
as literal text. An actual screen-reader client has not been exercised; automated
checks and keyboard traversal are not a WCAG certification. No dark theme or print/PDF
pipeline is added in this milestone.

The three bundled frontend assets use Prettier 3.6.2 defaults. Optional developer
formatting verification (Node/npm needed only for this check, never for the collector):

```powershell
npx --yes prettier@3.6.2 --check astrotrust/collector/static/index.html astrotrust/collector/static/collector.css astrotrust/collector/static/collector.js
```

The first invocation may download the development formatter. Python quality checks
and collector operation do not require Node. The existing CI runs backend tests and
both schema drift checks; the optional browser/axe and frontend formatting checks
are run locally rather than requiring browser downloads in the offline CI test job.
