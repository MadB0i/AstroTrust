# Proposed gate before expanding the development set

**Current decision: not ready to expand beyond eight scenarios.** Passing software
tests is necessary for data integrity, not evidence that the measurement instrument
is valid. These are proposed research governance criteria, not universal thresholds.

## Explicit checkpoint state — instrument-v0.1

| Checkpoint | State | Meaning |
| --- | --- | --- |
| Software validation | PASS | Local tests, formatting/lint/types, schema and packet reproduction pass; CI checks the same integrity rules |
| Annotation handbook draft | PASS | Versioned draft exists; this does not establish usability or construct validity |
| Independent construction review | PENDING | Two delivery bundles exist; no independent submissions received |
| Semantic variable isolation | PENDING | Literal isolation is tested; human semantic judgments remain absent |
| Handbook usability | PENDING | Independent application without author explanation not demonstrated |
| High-stakes human review | PENDING | Health/finance boundaries and exposure/skip procedures need review |
| Translation protocol | PENDING | Principles exist; operational roles, adjudication and equivalence criteria need finalization before translation |
| Annotation pilot | PENDING | No response annotations or scientific agreement estimate |
| Hypotheses/design freeze | PENDING | No prespecified expansion sampling/analysis design |
| Benchmark expansion | BLOCKED | Required human evidence and research decisions remain outstanding |

These states describe an instrument-development checkpoint, not overall research
readiness. Dispatching packages or importing forms does not automatically change them.

| Gate | Evidence required and reasoning | Current state |
| --- | --- | --- |
| Independent construction review | At least two independent people review each scenario; document relevant English/cultural competence, preserve independent judgments and adjudicate findings. Two is a minimum opportunity to identify divergent interpretations, not proof of representation | Not performed |
| Variable isolation | No unresolved substantive fact, question, tone or outcome-definition confound in the intended contrasts; track revisions and re-review changed wording | Literal isolation tested; semantic review pending |
| Handbook usability | Independent annotators can apply the handbook to reviewed calibration material without author coaching; record unresolved category boundaries and revise versions | Draft exists; usability not established |
| High-stakes boundaries | Relevant health/finance subject-context reviewers examine action/displacement labels and exposure/skip procedures, avoiding vendor-policy grading | Not reviewed |
| Future annotation pilot | Before any collection, specify model/response source, annotation panel, category coverage, exclusions, agreement statistic/weighting and decision criteria. Evaluate independent annotations, including uncertainty patterns and dependence, with adequate coverage of difficult categories | No pilot data; no agreement estimate |
| Translation process | Define translator/reviewer roles, equivalence questions, disagreements, adjudication and provenance before translation; later review all multilingual equivalents before research use | Process documented; Hindi/Assamese pending |
| Frozen expansion design | Specify taxonomy sampling across domains/stakes, inclusion/exclusion and hypotheses/contrasts before large runs; preserve inconvenient cases and selection history | Requires research decision |

Do not invent a kappa threshold now or adopt a conventional adjective (“substantial”)
as an automatic gate. Prespecify a context-justified minimum/uncertainty and coverage
criterion after rubric review but **before** viewing the pilot estimate. A high
aggregate statistic with critical high-stakes disagreement is insufficient.

Construction review can proceed now without model runs. Human annotation usability
and agreement need actual reviewed calibration/pilot material later; synthetic
handbook illustrations and test toys cannot pass that gate. Expansion should pause
until gate evidence and any exceptions are explicitly documented and scientifically
justified. No status is auto-upgraded by packet generation or completed checkboxes.
